# Verifier Bottleneck: пакет задания для Codex

Этот каталог является самостоятельным рабочим пакетом для реализации и проведения следующей серии экспериментов проекта **The Verifier Bottleneck: Can an AI Teach Itself Mathematics?**

## Что должен сделать Codex

Codex должен не просто написать код, а последовательно:

1. проверить среду и доступные вычислительные ресурсы;
2. прочитать исходные материалы и зафиксированные решения;
3. реализовать конечную песочницу композиции навыков с точным проверяющим модулем;
4. воспроизвести автоматические тесты генератора, операций, перебора и проверяющего модуля;
5. обучить стороннюю открытую модель атомарным навыкам через LoRA-подобный адаптер;
6. измерить исходную композиционную способность;
7. сравнить методы исследования пространства решений при строго одинаковом бюджете;
8. провести управляемое самообучение с точной проверяемой наградой;
9. проверить взаимодействие исследования пространства решений и качества проверяющей системы;
10. сохранить все конфигурации, журналы, контрольные точки, таблицы, графики и итоговый отчёт.

## С чего начать

1. Прочитать `AGENTS.md`.
2. Прочитать `PROMPT_TO_CODEX.txt`.
3. Прочитать документы в `docs/` по порядку номеров.
4. Запустить:

```bash
python scripts/preflight.py --output artifacts/environment/preflight.json
python -m pytest -q
python scripts/generate_smoke_data.py
```

5. Обновить `STATUS.md` по шаблону `STATUS_TEMPLATE.md`.
6. Не запускать дорогие серии до прохождения всех ворот качества из `docs/08_execution_runbook.md`.

## Главный научный вопрос

При фиксированном вычислительном бюджете помогает ли структурированное исследование пространства решений обнаруживать и закреплять новые композиции ранее освоенных атомарных навыков, или самообучение лишь перераспределяет вероятность уже доступных ответов?

## Основной заранее зафиксированный результат

Главное сравнение:

- стандартная независимая выборка кандидатов;
- структурированная выборка с балансировкой первого действия;

при одинаковом числе кандидатов, одинаковом лимите токенов, одной исходной модели, одинаковом LoRA-адаптере, точной проверяющей системе и трёх случайных запусках.

Основной показатель: изменение `pass@32` на закрытом наборе задач планирования композиции глубины 3 на простых числах, не использовавшихся при обучении.

## Структура каталога

- `AGENTS.md` - обязательные правила работы Codex.
- `PROMPT_TO_CODEX.txt` - готовое задание, которое можно вставить в Codex.
- `docs/` - полная научная и техническая постановка.
- `configs/` - исходные конфигурации экспериментов.
- `schemas/` - форматы данных и результатов.
- `src/vbexp/` - готовая основа конечной песочницы.
- `tests/` - автоматические проверки основы.
- `scripts/` - служебные команды.
- `materials/` - все исходные и производные материалы, переданные в разговоре.
- `manifests/` - происхождение файлов и контрольные суммы.

## Важное ограничение

Нельзя утверждать, что у базовой языковой модели вероятность решения строго равна нулю. В отчёте следует использовать формулировку **расширение эффективной достижимости при заданном бюджете**, а не абсолютное создание поведения из нулевой поддержки.
