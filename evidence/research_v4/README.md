# Проверка исправлений по второму отзыву

[Исходный отзыв](../../plans/source/22sept_iclr_feedback2/REVIEW_RU.md) относится
к `3d02434`. Исправления выделены в [план v4](../../plans/research_v4.json);
планы, данные и evidence v2/v3 остаются историческими.

| Замечание | Исправление |
|---|---|
| Q2 уже видел новые пары и depth4 | Original mask по умолчанию; exposure ledger по этапам; для confirmation — отдельный matching-mask SFT |
| Four-TARGET допускает TARGET-only решение | Paired crossed joint/cell, ordinary Hit@1/8 и correct mass; заранее заданная последовательность проверок |
| Редкий MC выглядит как численная ошибка | Отдельные статусы, ограниченные бюджеты 128/512/2048, те же train-панели, что у pilot |
| DSL меняет значения OP-токенов | Общий atomic PLAN/APPLY warm-up на 7/11/13, допуск по каждой операции, затем две ветки |
| Pilot мал для отрицательного вывода | Явная dev-кривая 1/2/4 для выбранной Q3/Q4 пары; целые панели как статистические единицы |

Регрессионные проверки включают TARGET-only контрпример, редкое событие
с нулевой MC-оценкой при ненулевом exact gradient, запрет чужой маски Q2,
подготовку matching-mask SFT, warm-up → continuation → оценку, защиту от
научного вывода на smoke-данных и перенос транзитивных зависимостей без весов.
Для проверки кода после закрытого научного допуска тест явно подменяет только
сам допуск; реальные gates случайной tiny-модели остаются закрытыми.

Команды и результаты — в [verification.json](verification.json), CPU/CUDA
логи — рядом. CUDA smoke выполнен вне sandbox на RTX 3050 Ti, BF16/FP32,
со случайной маленькой Qwen3. Проверяется forward/backward, Adam, сохранение
и загрузка, очередь, final без обучения, экспорт и анализ сохранённых оценок.
Полные Qwen3-0.6B/8B и A100-прогоны v4 здесь не выполнялись.

Полная генерация **v3** в [full_v3_data_audit.json](../../plans/source/22sept_iclr_feedback2/full_v3_data_audit.json)
выполнена автором отзыва: 64 crossed train-панели для каждой маски.
Локальная генерация v4 ограничена smoke. Историческая SFT-реконструкция
проверена отдельно; это не восстановленный фактический training log.

У Q2 matching-mask tiny MC при 16 группах неинформативен; один BF16 Taylor-check
для sampled MC mean превышает допуск (ошибка 0.00256). Gate имеет статус
`optimizer_check_failed`, `kernel_ok=true`; reward pilot не открыт.
DSL tiny также не проходит научный atomic gate (по 2 задачи на операцию).
Успешный smoke означает работоспособность кода и сохранение этих ограничений.
