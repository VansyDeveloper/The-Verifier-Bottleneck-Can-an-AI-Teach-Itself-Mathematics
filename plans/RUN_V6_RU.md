# Восемь пачек без промежуточного выбора

После feedback3 пользователь выбрал большой заранее заданный сбор. План v6 заменяет последовательность «R0–R3 → выбрать режим → CE/CF» для новых запусков. v4/v5 планы и полученные результаты сохранены.

## Состав и приоритет

Сначала пачки 1–4: CE против CE+CF при каждом сочетании LR `1e-4` / `3e-5` и replay `0` / `0.25`. Затем 5–8: те же сочетания для CE+H против CE+CF+H. Номера 1/5, 2/6, 3/7, 4/8 используют соответственно рецепты R0, R1, R2, R3 из прежнего плана.

В каждой пачке mask1/mask2 × seeds 0/1/2 × два метода: 12 обучений, всего 96. Одна база Qwen3-0.6B с hash `a3ca02aa9e41ea7899c5217bf766a596d369b9ff0f92d51320d5ad3d4327d938`. Это continuation seeds одной initialization.

Два прохода по 64 панелям, 128 updates, panel batch 1, BF16, prefix batch 16. CF weight 0.1, tau 1, entropy weight 0.01. Replay и monitor используют те же строки, что v5; отдельные manifests привязаны к v6 plan hash. Данные v4 заново не генерируются.

Каждая пачка выполняет 27 jobs: импорт, две initial full-dev оценки, 12 обучений и 12 full-dev оценок. Initial повторяется в независимых пачках ради простого запуска на разных серверах; это не новые независимые наблюдения. Другие пачки не нужны как входы.

## Запуск

Подготовка, таблица номеров и команда находятся в README. Оператору нужно заполнить путь к базе и выбрать свой заранее назначенный список номеров. Дальше запуск не требует решений по метрикам. На одном сервере `--gpus` задаёт локальные карты; на разных серверах номера распределяются вручную, без дублирования одного номера.

`--retry-failed` позволяет повторить ту же команду после технического сбоя. Завершённые jobs проверяются и пропускаются, training возобновляется с последнего целого checkpoint. Если изменились код или параметры, нужен новый output. Старые Q1/Q3 outputs не трогать; старую незавершённую очередь продолжают на её исходном commit.

Проверить план без обучения, например для пачки 1:

```bash
uv run python -m iclr.research plan --queue-name batch --batch 1 \
  --inputs outputs/shared_inputs_v4 --amendments evidence/research_v6/amendments \
  --models models.local.json --model-names q06 --out outputs/batch_1
```

Должно получиться `jobs=27`, `training_jobs=12`. Команда `start` из README планирует и запускает это сама. Для технического smoke нужны отдельные tiny inputs/model profile и `--smoke`: тогда одна маска, seed0, один update, шесть jobs. Такие результаты не входят в научную серию.

## Что сохраняется

На шагах 0/8/16/32/64/128 сохраняются adapter, Adam/RNG/cursor, журналы и fixed monitor. После каждого обучения автоматически выполняется полный dev. Метрики retention сохраняются и при плохом результате; они не отменяют последующие пачки. Полный dev всех промежуточных шагов сейчас не добавлен: веса остаются для последующей проверки выбранных шагов.

После каждой пачки автоматически создаётся `send_to_artem_exp_batch_<номер>_*.zip`. Его можно сразу пересылать, не дожидаясь остальных. Каждый ZIP распаковывается в свою папку. При технической ошибке команда из README собирает неполный ZIP с `partial` в имени; после повторного запуска нужен полный архив. В архиве:

- `START_HERE_RU.md`, `results/analysis/runs.csv` и `summary.csv`;
- сырые scores, ответы, monitor, atomic metrics и данные;
- queue/configs, training/replay streams, budgets, логи и receipts;
- `EXPORT_MANIFEST.json` с SHA256 и `DEPENDENCIES.json` с replay/monitor manifests.

Весов и `resume_state.pt` в ZIP нет. Полные `outputs/batch_<номер>/training/` хранить у оператора, включая промежуточные checkpoints. Без них позднее не сделать full dev нужного шага или resume. Новую копию архива можно собрать через `research send --out outputs/batch_1`; проверить — `research verify-bundle --archive ПУТЬ_К_ZIP`.

## Как потом сравнивать

Сначала сравнивать пары внутри одного LR/replay, на тех же masks/seeds и шаге. Например CE+CF − CE в пачке 1; CE+CF+H − CE+H в пачке 5. Пары 1/5, 2/6, 3/7, 4/8 дают эффекты entropy и CF×H. Разные рецепты не объединять в один средний CF effect без отдельного обоснования.

Показать все условия, включая неудачные по retention. Прежние пороги ≤5 п.п. потери навыков и ≥0.001 прироста correct mass остаются диагностическими отметками; в v6 они не управляют запуском. Успех только на TRAIN означает fitting.

Это широкое dev-исследование. Выбор лучшего из 96 результатов не превращает его обычный доверительный интервал в подтверждающий тест; сравнения множественные. Final остаётся закрытым. История базы по-прежнему ограничивает утверждения о невиденных парах, переносе длины и историческом рецепте. Q2 без своей проверенной initialization и gate, SIGReg, 8B, новая atomic-база и 256 updates в эту пачку не входят.

Время на A100 ещё не измерено. `wall_seconds` обучения включает monitor и начинается заново после resume; для общего GPU-времени нужны журналы всех попыток.
