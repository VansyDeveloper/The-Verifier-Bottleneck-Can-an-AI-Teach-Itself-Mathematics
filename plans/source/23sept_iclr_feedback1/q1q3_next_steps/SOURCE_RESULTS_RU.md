## Результат, который уже можно сформулировать

**Q1 показывает разрыв между условным различением программ и доступностью правильной программы для поиска.** Чекпойнты с меткой `composition` существенно лучше `atomic_control` выбирают правильную программу между двумя кандидатами при совместном изменении START и TARGET. При этом на обычных задачах с исключёнными парами операций правильная программа остаётся вне первой позиции, а попадание в top-8 и top-32 ухудшается. Вероятность правильной программы немного растёт, поэтому случайный поиск и поиск по рангу здесь движутся в разные стороны.

**Q3 пока не даёт положительного результата по основному критерию v4.** Все три варианта регуляризации имеют небольшой и неопределённый прирост strict crossed joint accuracy относительно CE. Сочетание CF и энтропии улучшает вторичную four-TARGET метрику и массу правильного решения, но сопровождается сильной потерей атомарных навыков. Это основание изучать компромисс между адаптацией и удержанием навыков, а не объявлять найденный метод композиционного переноса.

Обе серии — **dev**. У Q1 дополнительно не подтверждена история обучения фактически оценённых адаптеров: все шесть continuation bindings содержат `unrecorded_adapter_history`. Поэтому ниже «исключённые пары» означает устройство оценочного датасета; отсутствие этих пар во всей фактической истории Q1 ещё требует проверки.

![Основные контрасты, ранги и удержание атомарных навыков](overview.png)

На верхних панелях — парные 95% bootstrap-интервалы. На нижних — описательные кривые и точности для наблюдаемых запусков; новых независимых обучений эти линии не изображают. В Q1 кривые усреднены по трём continuation seeds и равновзвешенным B/D. Все интервалы условны на данных масках и чекпойнтах. [Векторная версия рисунка](overview.pdf).

| Начальная модель | Общий checkpoint с хешем `a3ca02…` | Тот же checkpoint |
| Данные | `original` | `mask1` |
| Оценённые состояния | Baseline; atomic-control и composition, seeds 0/1/2 | Initial; CE, CE+H, CE+CF, CE+CF+H, seed 0 |
| Обучение внутри очереди | Нет: оценка существующих адаптеров | 4 продолжения, по 2 эпохи |
| Подтверждённый бюджет Q3 | — | По 64 панели / 256 разных задач; 128 шагов; 512 предъявлений; 1 536 supervised operation tokens |
| Основная выборка B/D | 16 crossed-панелей + 50 four-TARGET панелей + 200 обычных задач на семейство | То же количество, другие задачи и маска |
| Фаза | dev, без analysis lock | dev, без analysis lock |

Q3 использовал `train_crossed.jsonl`: 39 разных witness-программ, единственное решение каждой задачи. Порядок всех 512 предъявлений побайтно одинаков в четырёх условиях. Общие параметры: learning rate `1e-4`, CF weight `0.1`, entropy weight `0.01`, tau `1`, dropout `0`, один panel на шаг. Сохранение/загрузка каждого нового адаптера дало нулевое расхождение на предусмотренном probe. Это содержательный matched pilot, хотя одной маски и одного seed недостаточно для подтверждения метода.

Семейства: **A** — известные поля, разрешённые пары операций; **B** — известные поля, исключённые пары; **C** — новые поля, разрешённые пары; **D** — новые поля и исключённые пары. Основной показатель — равное среднее B/D. Три пары `original`: `AX1→SH1`, `AC1→REV`, `SC2→AX1`; у `mask1`: `SC2→REV`, `SC2→SC2`, `SH1→SC2`. Абсолютные значения Q1 и Q3 нельзя объединять в одну выборку.

Сравнения используют **local prefix policy при temperature 1**. На глубине 3 она задаёт распределение по всем (5^3=125) программам. Full-vocabulary score с общей нормировкой листьев — отдельная политика; её результаты сохранены в CSV, но не смешиваются с основными.

В crossed-панели два START, два TARGET и две программы образуют четыре клетки с правильными ответами A/B/B/A. `Strict joint accuracy` требует правильного предпочтения во всех четырёх клетках. Политика, зависящая только от START, только от TARGET или только от самой программы, такой шаблон строго воспроизвести не может. При этом выбор между двумя специально подобранными программами существенно легче поиска ответа среди всех 125.

Four-TARGET pair accuracy проверяет согласованность пар назначений при одном START и четырёх TARGET. Это полезный вторичный показатель; он отдельно не устанавливает совместное использование START и TARGET.

Источник основных интервалов: [канонический v4 comparison](comparisons/Q1_composition_minus_atomic_control.json). Все они пересчитаны исходной функцией `iclr.research_analysis.compare` из архива. Интервал `[0; 0]` при Hit@1 описывает нулевые наблюдаемые парные разности в bootstrap; он не доказывает равенство истинных вероятностей на всех будущих задачах.

Прирост crossed joint положителен у всех трёх пар seeds: **+40,63; +28,13; +31,25 п.п.** По семействам: B **+43,75**, D **+22,92 п.п.** У D отдельный exploratory CI включает ноль: **[−4,17; 47,92]**; равновзвешенный результат B/D не доказывает эффект в каждом семействе по отдельности. Рост обычной точности сосредоточен в A/C: средний Hit@1 у composition равен 15,83% / 14,83% против 4,50% / 4,33% у atomic-control. Это разные направления изменения на разрешённых и исключённых парах; одно среднее по A–D скрывает эту структуру.

Crossed interaction (I), напротив, не увеличивается убедительно: разность **−1,21**, CI **[−6,40; 3,80]**. Величина логарифмического отрыва и доля панелей, где все предпочтения имеют правильный знак, здесь расходятся. Поэтому наиболее защищённый результат Q1 — конкретный прирост strict joint accuracy, а не общее утверждение об усилении любого показателя условности.

По правилу v4 получено `conditional_pattern=true`, `ordinary_solving_pattern=false`. `supports_joint_conditioning_claim=false` и `supports_task_solving_claim=false`: подтверждающая область эксперимента не выполнена. Неизвестная история адаптеров — дополнительное ограничение, не отражённое одним только значением `conditional_pattern`.

## 2. Почему ранжированный и случайный поиск дают разные результаты

Для задачи (i) обозначим через (m_i) суммарную вероятность её правильных программ в сохранённой local policy. Тогда вероятность хотя бы одного успеха в 32 независимых выборках с возвращением:

\[
S_i(32)=1-(1-m_i)^{32}.
\]

Ниже усредняется **сама (S_i) по задачам**, затем по seeds и B/D. Подстановка средней массы вместо отдельных (m_i) дала бы другое число. Это аналитическое вычисление из сохранённых вероятностей; новый sampled run или GRPO-эксперимент не выполнялся.

| Режим, Q1 B/D | Atomic-control | Composition |
|---|---:|---:|
| Top-32 разных программ по рангу, Hit@32 | 25,58% | 9,58% |
| Хотя бы один успех за 32 IID-выборки, рассчитанная вероятность | 2,38% | 7,64% |
| Доля вероятности всех программ, содержащих исключённую пару | 0,90% | 2,32% |
| Hit@1 после ограничения кандидатов этим пулом | 5,92% | 21,58% |
| Hit@8 после такого ограничения | 39,50% | 62,92% |

Последние две строки — **post-hoc диагностика с использованием структуры тестового семейства**, не оценка нового готового метода. В `original` такой пул содержит 29 из 125 программ. Она показывает, что внутри соответствующего пула правильный кандидат располагается выше у composition, но всему пулу выделено мало вероятности. Это согласуется с сочетанием условного сигнала и сильного предпочтения других программ. Одного этого разложения недостаточно для причинного объяснения устройства нейросети.

Exploratory парные интервалы: прирост рассчитанного sampled-успеха **+5,26 п.п. [4,19; 6,34]**, прирост restricted Hit@1 **+15,67 п.п. [11,92; 19,50]**. Они не скорректированы за выбор дополнительных диагностик и не входят в fixed sequence v4. Источник — [exploratory_contrasts.json](exploratory_contrasts.json).

Арифметический ориентир при одном правильном ответе и равномерном распределении по 125 программам: масса **0,8%**, Hit@32 случайной перестановки **25,6%**, успех 32 IID-выборок **22,67%**. Composition остаётся ниже этого ориентира для ordinary B/D. Успех диагностического различения ещё не превращается в полезный поисковый приоритет в полном пространстве.

Практический смысл для verifier bottleneck: верификатор может использовать только фактически предложенные решения. Q1 поддерживает более узкую картину — условная информация и вероятность обнаружения решения могут меняться по-разному. Доказательства улучшения reward-обучения эти два архива не содержат: результатов Q2 здесь нет.

## 3. Q3: вторичный сигнал есть, основной критерий не пройден

CE — cross-entropy по обучающей программе; CF — counterfactual loss по crossed-панели; H — бонус энтропии local policy. Все значения ниже — B/D, depth 3, local policy; четыре обученных условия имеют Hit@1 = Hit@8 = 0%.

| Условие | Crossed joint | Crossed cell | Four-TARGET pair | Hit@32 | Correct mass |
|---|---:|---:|---:|---:|---:|
| Initial | 9,38% | 56,25% | 55,25% | 56,50% | 1,3225% |
| CE | 6,25% | 51,56% | 55,75% | 11,75% | 0,0934% |
| CE + H | 9,38% | 53,91% | 59,00% | 8,75% | 0,1234% |
| CE + CF | 9,38% | 53,13% | 58,00% | 11,00% | 0,1035% |
| CE + CF + H | 9,38% | 52,34% | 65,75% | 14,00% | 0,1970% |

Предусмотренный screening-контраст **CE+CF − CE** даёт crossed joint **+3,13 п.п. [−6,25; 12,50]**. Это один дополнительный успех на 32 панелях B/D. Прирост crossed cell **+1,56 п.п. [−3,91; 7,05]** также неопределён. Во всех альтернативных сравнениях с CE основной strict joint прирост составляет те же +3,13 п.п. с интервалом, включающим ноль. Основания отвергнуть весь класс методов нет; основания объявить победителя по первичному критерию тоже нет.

При этом CF-компонент действительно присутствует в сохранённых training logs: у CE+CF его среднее по эпохе снижается с **0,571 до 0,131** на одном и том же наборе train-панелей. Все 128 шагов каждого условия завершены; зарегистрированная норма градиента до clipping превышает порог 1 на каждом шаге. Улучшение обучающего loss здесь не сопровождается убедительным приростом первичной dev-метрики.

У **CE+CF+H** four-TARGET pair accuracy выше CE на **10,00 п.п. [5,83; 13,92]**, а correct mass примерно в **2,11 раза** больше. Это вторичные exploratory результаты. Первый тест fixed sequence не пройден, поэтому ими нельзя заменить подтверждающий вывод о START × TARGET или решении обычных задач.

Рост correct mass у комбинации сопровождается увеличением массы всего пула исключённых программ: **1,47% → 2,82%**. Средняя условная вероятность правильного решения внутри пула меняется гораздо меньше: **6,20% → 6,27%**. Это диагностический аргумент в пользу перераспределения вероятности между пулами; формальное причинное разложение эффекта здесь не проводилось. Настоящий factorial-контраст `CE+CF+H − CE+CF − CE+H + CE` для four-TARGET равен **+4,50 п.п. [−1,25; 10,34]**: синергия по этой метрике не установлена. Для crossed joint взаимодействие равно **−3,13 п.п. [−18,75; 12,50]**. Полное разложение сохранено в [exploratory_contrasts.json](exploratory_contrasts.json).

Исключённый пул на `mask1` содержит 26 программ. У initial на него приходится **96,73%** вероятности, тогда как в Q1 initial/baseline на пул другой маски — **0,86%**. Начальный top-1 на mask1 B/D — `SH1 SC2 REV` в 312 из 400 задач; эта программа содержит пары, исключённые именно в mask1. Поэтому большие различия raw Hit@32 между масками могут возникать из-за совпадения структуры маски с предпочтениями исходной политики. Это ещё одна причина сохранять парные сравнения внутри каждой маски.

## 4. Атомарные навыки: сильное ограничение интерпретации Q3

PLAN выбирает одну операцию по START/TARGET; APPLY вычисляет результат уже заданной операции. На каждом наборе — 1 000 задач, по 200 на операцию.

| Q3 | Atomic PLAN | Atomic APPLY | Корректный формат APPLY |
|---|---:|---:|---:|
| Initial | 99,2% | 62,7% | 100,0% |
| CE | 39,5% | 15,8% | 77,2% |
| CE + H | 45,8% | 18,2% | 58,2% |
| CE + CF | 32,0% | 34,6% | 100,0% |
| CE + CF + H | 32,8% | 29,1% | 100,0% |

Формат PLAN корректен в 100% ответов всех условий: падение PLAN не объясняется парсером. Все четыре продолжения имеют **0% PLAN для SC2**. У APPLY часть потерь CE/CE+H связана с форматом, но CF-условия сохраняют формат и всё равно заметно уступают initial по правильности. Называть результат только проблемой формата нельзя.

Исходная модель уже имеет неравномерные атомарные навыки: APPLY SH1 = **0/200**, SC2 = **27/200**, остальные три операции — **200/200**. Это наблюдается до Q3. Почти идеальный PLAN не доказывает владения выполнением всех примитивов. Поэтому эти данные не поддерживают предпосылку «все атомарные операции освоены, остаётся только научиться их композиции».

Q1 отличается: atomic PLAN у composition в среднем **98,23%**, APPLY **61,93%**; у atomic-control **99,37%** и **72,53%**. И здесь SH1 APPLY равен нулю во всех семи состояниях. Контраст Q1/Q3 не является чистой абляцией replay или TRACE: различаются маски, бюджеты и рецепты, а история Q1 не подтверждена. Объяснение потери навыков отсутствием atomic replay в Q3 остаётся проверяемой гипотезой.

## 5. Что означает рост энтропии

В ordinary B/D **все 400 задач имеют ровно одно правильное решение**. Поэтому энтропия распределения внутри правильного множества равна нулю. Предусмотренный показатель `ordinary_multiple_solution_correct_entropy` недоступен во всех сравнениях; отсутствие значения нельзя заменять результатом на многоответных задачах.

Для Q1 B/D общая энтропия программ растёт с **0,754 до 3,754 nat**. Энтропия по различным аффинным функциям растёт с **0,752 до 3,417**, а условная энтропия записей одной и той же функции — с **0,002 до 0,338**. Около **88,8% прироста** общей энтропии приходится на различие функций. При массе правильного ответа менее 0,3% это в основном разнообразие неправильных вариантов.

Разложение по правильности имеет вид (H=H_b(m)+mH_{correct}+(1-m)H_{incorrect}). Здесь (H_{correct}=0). Поэтому «больше энтропия» не эквивалентно «больше разнообразных правильных рассуждений».

Положительное post-hoc масштабирование всех program scores температурой сохраняет ранги; сохранённые температуры 0,5/1/2 дают одинаковые Hit@K. Оно может изменить вероятность sampled-успеха, но не исправить текущий top-K порядок. Это утверждение относится к масштабированию **готовых program scores**, а не к изменению температуры каждого следующего токена.

В малой диагностике `results/evaluations/*/solutions.json` первые 8 ordinary-задач каждого из B/D на depth3 дают **0/16** успехов constrained greedy у каждого из 12 чекпойнтов. Свободная генерация также имеет 0/16 успехов и 0/16 корректных форматов по реализованному парсеру. Это выборка по порядку файла, а не дополнительная независимая оценка точности; основные результаты выше основаны на полном пространстве программ.

## 6. Достоверность, история обучения и область статистического вывода

**Что проверено локально.** Все 786 файлов, перечисленных в двух export manifests, прошли проверку размеров и SHA-256. Целые ZIP также зафиксированы SHA-256. Архивный код побайтно совпал с `artem_iclr` на commit `c37cfe083787f21af9a9aab0ef1d02c63cf603d3`; read-only проверка GitHub подтвердила этот HEAD в начале разбора. Все 8 jobs Q1 и 10 jobs Q3 имеют статус `done`.

Для всех **28 192 task/run записей** пересчитаны local/full scores из сохранённых префиксов и все сохранённые entropy/rank метрики при трёх температурах. Максимальное расхождение восстановления scores — **7,63×10⁻⁶**, в пределах различий CPU/GPU вычислений FP32; максимальное расхождение пересчёта метрик — **4,45×10⁻¹⁵**. Правильные множества проверены заново точными аффинными преобразованиями. Crossed/four-TARGET метрики независимо собраны из score-матриц и совпали с архивными значениями. Проверены dataset manifests, completion receipts и связь четырёх Q3 training receipts с оценёнными адаптерами. Это воспроизведение анализа сохранённых данных; веса, фактическое обучение и новый модельный инференс не воспроизводились.

**Что осталось неизвестным у Q1.** Во всех трёх `composition` и трёх `atomic_control` bindings текущий `adapter_hash` отсутствует в `historical_exposure` датасета. Например, у composition seed0 оценён `a7ea007c…`, а исторический реестр содержит `074b889f…`. Поэтому код записал `unrecorded_adapter_history` и `recorded_history_excludes_mask=false`. Последнее здесь означает отсутствие подтверждённой истории, **не обнаруженную утечку**. Аналогично `historical_depth4=false` при неизвестной истории нельзя читать как доказательство отсутствия depth4 в обучении.

Старые рецепты в `code/evidence/upgrade/previous_q06.json` принадлежат другим payload hashes. Их число эпох, replay=0.2, TRACE и бюджеты нельзя автоматически приписать новым Q1 адаптерам только из-за похожих имён каталогов. Даже если расхождение вызвано переупаковкой тех же весов, эту связь требуется установить по артефактам. Общая atomic base также дана своим хешем и объявленной ролью; receipt её собственного обучения в этих двух экспортированных очередях отсутствует.

Чтобы закрыть пробел без передачи больших весов, достаточно запросить у оператора для **фактических шести Q1 run directories** их training config, `DONE`/`TRAINED` или эквивалентный receipt с payload hash, `budget.json`, training/data manifest и сведения об исходной модели; если есть `training_stream.jsonl`/`exposure.json` — их тоже. Для новой atomic base нужен её training receipt/config/manifest. Если receipts относятся к прежней упаковке адаптера, понадобится отдельная проверка соответствия весов старого и текущего payload. До этого корректно говорить о различии оценённых чекпойнтов, а причинную интерпретацию рецепта и «никогда не виденные пары» оставлять условными.

**Статистика.** Использован неизменённый v4 plan: 2 000 парных bootstrap-ресэмплов, сначала усреднение continuation seeds, затем ресэмплирование целых панелей; ordinary задачи группируются по `(field, START)`. У данной ordinary B/D выборки это по 200 разных кластеров на семейство. B и D получают одинаковый вес. Четыре клетки одной панели и три повторные оценки одной задачи не выдаются за независимые задачи. Seed-уровень не ресэмплируется; CI не оценивает вариативность новых полных обучений или новой atomic initialization.

Primary Q1/Q3 comparisons используют порядок и RNG исходного анализатора. Дополнительные интервалы используют то же количество draws и seed, но отдельные RNG-последовательности для каждой метрики; поэтому их границы могут немного отличаться от канонических на совпадающих endpoints. Основные интервалы в таблицах берутся из `comparisons/`, новые диагностики — из `exploratory_contrasts.json`.

Первая проверка v4 — positive lower CI crossed joint и неотрицательная crossed cell разность. Вторая — positive lower CI ordinary Hit@1 при неотрицательных Hit@8 и correct mass — открывается только после первой. Остальные интервалы описательные; p-values и новый скорректированный omnibus-тест здесь не конструировались. Подтверждающий статус протокола требует final, масок 1/2 и paired seeds 0/1/2. У этих архивов такого покрытия нет.

**Методологический разбор: 11/11 типов проверено.**

## 7. Выводы для дальнейшей работы

1. **Основной результат этих двух архивов — измеренный разрыв между условным выбором и обычным поиском решения.** Для Q1 он виден одновременно в crossed joint, full-space Hit@K, правильной вероятностной массе и restricted-pool диагностике. Разрыв можно обсуждать уже сейчас с указанием dev-статуса и отсутствующей истории адаптеров.
2. **Q3 полезен как отрицательный screening текущего режима и диагностика удержания навыков.** Он не подтверждает пользу CF по первичному endpoint и не опровергает CF/entropy как класс. Комбинация CF+H имеет вторичный сигнал, но не показала убедительного factorial-эффекта по four-TARGET или crossed joint.
3. **Первый шаг для усиления Q1 — восстановить provenance, затем использовать предусмотренную закрытую оценку.** Final на original проверит воспроизводимость диагностического результата на новых задачах этой маски; перенос на новые маски она сама по себе не установит.
4. **Перед масштабированием Q3 стоит понять потерю атомарных навыков на dev.** Предусмотренная кривая бюджета 1/2/4 эпох может проверить зависимость эффекта от длительности при явно выбранной паре условий. Replay, уменьшение learning rate или другой рецепт — отдельные гипотезы; текущие архивы не позволяют выбрать причину потери навыков. Новые обучения, выбор победителя и analysis lock в этом разборе не создавались.

Эти данные не доказывают восстановление общего математического рассуждения, преимущество reward/GRPO, length extrapolation или независимую воспроизводимость на новых базовых инициализациях. Положительный вывод уже достаточно конкретен: **на наблюдаемых Q1 чекпойнтах сильнее условное различение пар программ, но этого недостаточно для улучшения решения ordinary B/D в полном пространстве кандидатов.**

## Воспроизведение и файлы

Скрипт использует исходный анализатор непосредственно из проверенного ZIP и не зависит от текущей рабочей ветки. Нужны оба исходных ZIP, Python с `numpy`, `scipy`, `torch`, `matplotlib`; веса модели и GPU не нужны. Из корня этого репозитория фактически выполнено:

```bash
/tmp/artem_iclr/.venv/bin/python analysis/iclr_v4_q1_q3_20260922/analyze.py
```

Переносимый вариант из окружения с указанными пакетами:

```bash
python analyze.py --archives /path/to/two_zip_files --out /path/to/new_analysis
```

При обычном повторе результаты вычислений перезаписываются в выбранном `--out`; исходные ZIP читаются. Полный replay проверяет все строки, поэтому занимает несколько минут.
