# Дополнение от 21 сентября: перенос и предпочтения программ

Основание: [исходный запрос](source/goal_to_iclr.md), сохранённый без правок.
Код и очередь готовы; новые полные обучения и новая оценка прежних весов
на удалённом компьютере **ещё не выполнены**. Локальные короткие запуски
проверяют работоспособность и не входят в научные результаты.

## Что уже выполнено

В пакетах 0.6B и 8B подтверждены по шесть continuation runs: atomic control
и composition, seed 0/1/2. Проверены DONE/TRAINED, ранжирования, промежуточная
и последняя оценки, summary и внутренний CSV. Другие ячейки прежних
`replay/trace/set` в найденных пакетах не обнаружены.

| Старый dev, среднее трёх seed | SFT raw Hit@32 | SFT A-only full | Atomic A-only full |
|---|---:|---:|---:|
| 0.6B, B | 7,83% | 56,00% | 44,00% |
| 0.6B, D | 4,50% | 49,00% | 39,50% |
| 8B, B | 8,33% | 58,33% | 33,83% |
| 8B, D | 7,50% | 57,50% | 35,33% |

Это вмешательство в сохранённый score на открытом dev. Веса и исходная
вероятность решения модели не менялись. Для A применён crossfit из пяти
частей; для B/C/D поправка оценена только по A, alpha=1. Результаты по seed,
H(K), коэффициенты и provenance: [evidence/upgrade](../evidence/upgrade/README.md).
Внешний CSV 8B содержит 18 расхождений с согласованными JSONL/summary/CSV
внутри ZIP; причина не установлена, обе версии сохранены в отчёте.
Повторный inference прежних весов при этом анализе не выполнялся.

## Зафиксированный протокол

Полный локальный набор: 72 000 новых задач и 40 000 строк повторно используемого
atomic train (по 5 000 в каждом из восьми каталогов). Независимый полный
перебор интерпретатором подтвердил correct sets, минимальную глубину,
ограничения и отсутствие общих состояний с прежними данными:
[аудит](../evidence/upgrade/full_data_audit.json). Новых модельных результатов
на этом наборе пока нет.

* В каждом каталоге train=5 000; dev/final A/B/C/D по 200; calibration A=200
  отдельно от dev/final; atomic dev/final по 200 на операцию. В `original`
  дополнительно final глубины 4 по 200 на семью и по 50 панелей из четырёх
  TARGET на семью. A/C: все решения избегают ограничения; B/D: все решения
  содержат ровно одно нарушение. C/D используют новые поля.
* В `original` и четырёх масках совпадают train-страты по полю, степени и
  числу решений: 60%/20%/20% задач с 1/2/3 решениями, с округлением внутри
  страты. Частоты пяти операций отличаются максимум на один внутри страты.
  Квоты выбраны до получения модельных результатов.
* Размеры страт учитывают свободные состояния после прежнего набора.
  F5/degree3 исключена из всех пяти matched train: полный перебор оставшихся
  START не нашёл необходимых задач с тремя решениями. Это не исключение
  из всех тестов. Основание: [protocol](../evidence/upgrade/data_protocol.json),
  [finite-state preflight](../evidence/upgrade/finite_state_preflight.json).
* Witness-сравнение имеет отдельный общий train с двумя правильными
  программами на задачу. Uniform выбирает ответ заново при предъявлении;
  balanced жадно уменьшает сумму квадратов частот разрешённых пар. Это
  эвристика, не обещание одинаковой частоты каждой пары.
* Новая тройка — SH1, SC2, REV; обе составляющие пары встречаются в train.
  Позиционный тест исключает SH1→SC2 в позиции 0 и предъявляет её в позиции 1
  (нумерация с нуля). Ограничения проверяются по всем правильным решениям.
* Все правильные траектории разделены между train/calibration/dev/final
  внутри каждого каталога. Общие состояния разрешены внутри одной панели
  START. Между независимыми наборами разных масок пересечения допустимы.
  Atomic train намеренно общий.

Маски: `mask1={SC2→REV, SC2→SC2, SH1→SC2}`;
`mask2={AX1→REV, SH1→REV, SH1→SC2}`;
`mask3={REV→SC2, REV→SH1, SH1→REV}`;
`mask4={AX1→REV, SC2→AX1, SH1→REV}`.
Семь невозможных одиночных ограничений проверяются отдельно. Число классов
функций в `mask_feasibility.json` не объявляется числом задач.

Генерация сохраняет manifest до модельной оценки. На другой машине MILP
с ограничением времени может выбрать другой допустимый целочисленный план.
Для побайтного повтора переносите сам каталог данных с его SHA-256;
одного seed недостаточно. Аудит обязателен и на удалённой машине.

Новые trace-пары: composition replay=0.2, два прохода по 6 250 предъявлений
(все 5 000 matched composition задач + 1 250 atomic). Это сохраняет заданные
частоты операций и страты в фактическом обучении; смесь из 5 000 предъявлений
использовала бы лишь 4 000 composition задач. Atomic control replay=1 совпадает
с этой веткой по target tokens и шагам. Прежние runs не переопределяются.
Witness-пары: PROGRAM-only, replay=0, два прохода по 5 000, dropout=0,
одинаковые задачи и порядок. Фактические budgets и ответы записываются.

`set_mass` и `single_norm` используют глобальную нормировку full-vocabulary
score по листьям. Local action-policy вычисляется только по настоящим
префиксам; из старых leaf scores её не восстанавливаем. IID pass@K считается
по правильной массе каждой задачи; общая энтропия его не определяет.

Reward control: одна исходная SFT-модель, одинаковый порядок задач, G=32,
температура 1 в sampling/loss, dropout выключен в обоих местах, KL beta=0.
Точное ожидание относится к reward-градиенту с population std. Pilot:
четыре SGD-шага, lr=1e-5, без clipping. Full: 158 шагов AdamW, lr=1e-4,
clipping=1, одна задача на шаг в обеих ветках. Это отдельный контроль,
не повтор старого GRPO-протокола; равенство ожидаемых шагов Adam/clipping
не утверждается. Full зависит от успешных квитанций всех четырёх pilot.

AC1/AX1/REV заранее выбраны по историческому Qwen APPLY как кандидаты для
структурной страты. Надёжность нужно проверить по новым atomic и
true-intermediate результатам, в том числе для другой семьи. PLAN, разбор
текста и семантическое исполнение сохраняются отдельно.
Внешняя репликация: [SmolLM2-1.7B](https://huggingface.co/HuggingFaceTB/SmolLM2-1.7B),
revision `effd688a12921b4cc83e3312b6feb579f70f9c71`. Полные веса локально не
загружались. Свежие Qwen continuation на том же `original` отделяют смену
семьи от смены train-протокола прежней серии.

## Запуск на одном или нескольких компьютерах

Актуальная операторская инструкция находится в [основном README](../README.md):
шесть смысловых блоков, общий архив входных данных, команда `start`, список GPU,
разделение по seed и автоматическая посылка `send_to_artem_exp_…` без весов.
Прежняя очередь обучения не повторяется. Блок 01 только заново оценивает
прежние веса на новых задачах и сохраняет отсутствовавшие prefix probabilities.

Независимые блоки можно запускать на разных компьютерах. Блоки 01–04 также
делятся по seed; пары веток остаются вместе. Блоки 05/06 запускаются целиком
из-за общих pilot-зависимостей или новой atomic initialization. На всех
машинах одинаковые shared inputs и исходные веса, проверяемые по SHA-256.

Ожидаются A100; SSH-адрес, число GPU и текущие пути весов оператор проверяет
на своей машине. Исторические пути заданы в `plans/upgrade_models.json`.
Для 02–04 проверяется только atomic 0.6B; ненужные старые adapters/8B не требуются.

## Скачать и анализировать

После успешного `start`/`run` уже создаётся папка `send_to_artem_exp_…` и ZIP.
Для дополнительной сводки или архивирования вручную:

```bash
uv run python -m iclr.upgrade collect --out outputs/upgrade_20260921
uv run python -m iclr.upgrade bundle --out outputs/upgrade_20260921 \
  --archive outputs/upgrade_20260921_results.zip
```

`bundle` также выполняет `collect`, проверяет квитанции и каждый файл ZIP
по SHA-256. По умолчанию веса исключены; `--include-models` добавляет веса
новых запусков внутри очереди. Прежние inherited weights хранятся отдельно.
Частичный экспорт требует `--allow-incomplete` и маркируется `partial`.
Во время работающих процессов экспорт отклоняется.

На своём компьютере, подставив действительный SSH-адрес и путь:

```bash
scp user@host:/workspace/verifier-bottleneck/outputs/upgrade_20260921_results.zip .
python -m iclr.upgrade verify-bundle --archive upgrade_20260921_results.zip
unzip upgrade_20260921_results.zip -d upgrade_20260921_download
```

Проверка ZIP требует только стандартную библиотеку Python и этот код;
CUDA, веса и прежние пути outputs не нужны. Содержимое:

| Путь | Назначение |
|---|---|
| `EXPORT_MANIFEST.json` | Полнота, наличие весов, SHA-256 и размер файлов |
| `results/analysis/runs.csv` | Все задания/статусы и пути относительно `results/` |
| `results/analysis/summary.csv` | Общая таблица по run/seed/семье/depth/scorer/калибровке/TARGET control; хеши данных и весов |
| `results/experiments/<block>/evaluations/<run>/task_metrics.csv` | Метрики каждой задачи для парного анализа |
| `results/experiments/<block>/evaluations/<run>/hitk.json` | H(K), K=1…125 или 625 |
| `results/experiments/<block>/evaluations/<run>/{rankings,prefixes,calibration_rankings}.jsonl` | Сырые score, prefix probabilities, calibration A |
| `results/experiments/<block>/evaluations/<run>/execution.jsonl` | Ответы atomic/true-intermediate/program execution |
| `results/experiments/<block>/training/<run>/` | Budgets, training stream, witness, метрики, reload, прежний eval и квитанции |
| `results/data/` | Задачи, ограничения, manifests и протокол |
| `results/reference_data/` | Прежние исходные задачи для повторного аудита исключений без доступа к серверу |
| `code/` | Исходники, uv.lock, инструкции и прежние доказательные отчёты |

Сравнивайте seed по одинаковому data_hash и task_id. Панели, final, глубина 4
и wrong-target — разные evaluation_set/control. Старый dev, прежняя
confirmatory-серия, новая closed evaluation и локальные smoke остаются
разными уровнями свидетельств; общий CSV их не усредняет.
