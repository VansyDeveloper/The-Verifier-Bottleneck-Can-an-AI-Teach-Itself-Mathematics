# Кто что делает

По переписке 3–10 сентября 2026 года:

- Дима: GRPO и его диагностика, выбор разнообразных траекторий, исключение 1/2/3/5 пар операций.
- Артём: H(K) и ошибки, сохранение атомарных навыков, обучение с промежуточными состояниями и без них, все правильные программы, другая модель, текст статьи.
- Андрей: запускает [подготовленные расчёты](../README.md) и возвращает результаты.

Очереди Артёма:

- `replay`: замена 0/10/20/40% примеров атомарными при равном числе предъявлений; отдельный атомарный контроль по числу обучающих токенов.
- `trace`: одна выборка с 20% атомарных примеров, программа с TRACE и без; дополнительный контроль по числу токенов.
- `set`: глубина 3, без атомарных примеров; обычное обучение на одной программе, нормированная вероятность одной программы, суммарная вероятность всех правильных. В двух последних вариантах вероятность нормируется внутри 125 программ; это не вероятность свободного текстового ответа.
- `size`: основная пара «атомарный контроль / 20% + TRACE» на Qwen3-0.6B и Qwen3-8B. Оба размера в BF16, каждому нужна собственная атомарная подготовка. Сначала seed 0 для замера, затем 0/1/2; другие эксперименты на 8B автоматически не повторяем.

Общие расчёты используются повторно. Задачи Димы в эти очереди не входят.
По умолчанию: 3 seed, 2 эпохи, batch 64; 5000 задач глубин 2/3/4 в пропорции 1:2:1. Это предварительная серия: при трёх seed минимальное двустороннее p точного теста смены знаков равно 0,25. Данные новые; параметры выбираются на dev, final автоматически не оценивается. Фактические токены, время и память сохраняются для каждого расчёта.
Интервалы сейчас учитывают разброс между seed. Двойной bootstrap по seed и задачам ещё не реализован.

TRACE следует после программы, поэтому опыт проверяет дополнительное обучение на состояниях. Рост вероятности правильных программ сам по себе не доказывает рост разнообразия.
В `set` исключённые пары отсутствуют среди правильных обучающих решений, но могут встречаться среди отрицательных кандидатов.
Внешний набор данных и новый опыт с шумным верификатором не согласованы. В статье остаётся ограничить общие выводы о GRPO и «two-dial law», отделить решения внешнего поиска от самостоятельного поиска модели и уточнить статусы опытов второй серии.
